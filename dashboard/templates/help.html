Overview

Fetchproxies is a snapshot queue that runs your URL through ten parallel extractors and stores every artifact on disk under a stable ID. Every outbound HTTP request leaves through a chain of proxies — Mullvad rotation first, Bright Data as fallback — so the upstream sees a fresh egress and the host stays unidentified.

Fronted services

URLs are transparent. twitter.example.com/elonmusk works the same way twitter.com/elonmusk does — same path, same query, just routed through a private frontend.

Public proxy proxy.example.com

Use the host as a forward proxy from any tailnet host. All three flavours fan into the same in-guest archiver chain (Mullvad rotation → Bright Data fallback). Bound to 127.0.0.1 + the host's tailnet address (100.x.y.z) only — never publicly reachable.

ProtocolEndpointNotes
SOCKS5100.x.y.z:1080plaintext over tailscale (already encrypted hop-by-hop)
HTTP forward100.x.y.z:8118handles http:// and CONNECT-tunneled https://
HTTPS forwardproxy.example.com:8443TLS-terminated with the example.com wildcard cert
Browser GEThttps://proxy.example.com/302 → fetch.example.com (so a stray browser hit doesn't hang)
curl examples 
# SOCKS5
curl --socks5 100.x.y.z:1080 https://api.ipify.org

# HTTP forward proxy (also tunnels HTTPS via CONNECT)
curl -x http://100.x.y.z:8118 https://api.ipify.org

# HTTPS forward proxy (TLS-wrapped)
curl -x https://proxy.example.com:8443 https://api.ipify.org

Profiles

Pick one when submitting a snapshot — fans out into one row per extractor.

  • full→wget_warc, monolith, screenshot, screenshot_mobile, screenshot_tablet, screenshot_desktop, readability, pdf
  • compare→full + bd_screenshot mullvad-vs-bright-data side-by-side
  • screenshots→screenshot_mobile, screenshot_tablet, screenshot_desktop, screenshot resolution sweep, no archive
  • lightweight→monolith, readability
  • media→yt_dlp
  • warc_only→wget_warc
  • bd_only→bd_screenshot

Proxy chains

Defined in services.fetchproxies.proxy-chain.chains (the host's configuration.nix). gost v3 with strategy=fifo — first backend wins, dead ones skipped for failTimeout.

Full machine-readable spec at /api/openapi.json.

MethodEndpointPurpose
GET/api/v1/statsSnapshot + artifact counts
GET/api/v1/snapshotsRecent 100 (filter via ?state=, ?url=, ?tag=)
POST/api/v1/snapshotsCreate one or many snapshots
POST/api/v1/snapshots/manualCreate a manual snapshot — title + html/markdown/custom blobs, no worker fetch
GET/api/v1/snapshots/<id>One snapshot
GET/api/v1/snapshots/<id>/resultsExtractor rows
GET/api/v1/snapshots/<id>/artifactsFiles written by completed extractors
POST/api/snapshots/<id>/retryRequeue every failed/skipped result
POST/api/snapshots/<id>/cancelMark pending+running results skipped
POST/api/snapshots/<id>/deleteCascade-delete the row
POST/api/snapshots/<id>/rearchiveNew single-snapshot run with same URL/tags/extractors
POST/api/results/<id>/retryRequeue one extractor row
GET/api/v1/proxy/healthPer-backend health from proxy-probe
GET/api/v1/exportFull JSON dump (runs + snapshots + results + artifacts)
Submit via curl 
# single URL
curl -sX POST https://fetch.example.com/api/v1/snapshots \
  -H 'content-type: application/json' \
  -d '{"url":"https://example.com","profile":"compare","tags":["sample"]}'

# batch (one run, many snapshots)
curl -sX POST https://fetch.example.com/api/v1/snapshots \
  -H 'content-type: application/json' \
  -d '{"urls":["https://a.com","https://b.com"],"profile":"full"}'

# manual (no worker fetch — you supply the content)
curl -sX POST https://fetch.example.com/api/v1/snapshots/manual \
  -H 'content-type: application/json' \
  -d '{"url":"https://example.com/note","title":"My note",
       "html":"<article>…</article>",
       "markdown":"# heading\n\nbody",
       "custom_contents":[{"key":"transcript","content":"00:00 …"}],
       "tags":["manual","note"]}'
